# Нижнє меню

`GlassTabBar.tsx` підключене через `tabBar` у `src/app/(private)/(tabs)/_layout.tsx`. П’ять вкладок: головна, легалізація, блог, профіль, партнери. Сторінки деталей та авторизація меню не мають.

## Макет і бібліотека

Джерело: [Figma — Biblioteka / Residdy / Navigation / Main / Active=Home](https://www.figma.com/design/cxackiDw0sh8Y24QgXGmoT?node-id=288-7145).

Стандартний режим: п’ять іконок без видимих підписів, висота 72, радіус 36, внутрішній відступ 8 разом із бордером. Бордер білий 30%, активна підкладка біла 35%, радіус 28. Ширина — 95% доступного місця після бічних відступів 16 і safe area; меню центроване (приблизно 340 при ширині екрана 390). Іконки — з `assets/system_icons/menu`, надані користувачем. Використано готові GlassCard / Card, без нових залежностей.

Підкладка пересувається через Animated.spring, активна іконка масштабується до 1.1. Native driver; немає таймерів чи постійного анімаційного циклу. Tab events і preventDefault збережені. Активність визначає Router, а не дубльований локальний стан.

## Доступність і платформи

- Мінімальна область натискання 48 × 56. Кожна вкладка має перекладену accessibilityLabel та selected.
- При fontScale > 1.2 з’являються підписи, ширші кнопки й більші іконки. Меню прокручується горизонтально, активний пункт потрапляє у видиму область. Текст масштабується системою, без numberOfLines або обмеження maxFontSizeMultiplier.
- При збільшеному масштабі дисплея меню реагує на фактичну доступну ширину. Висота не фіксована: у великому режимі росте разом із текстом.
- Reduce Motion вимикає пружини, зум і плавну автопрокрутку. Reduce Transparency на iOS замінює скло непрозорим Card.
- Меню займає місце в layout, не накриває контент сторінки. Нижній safe area врахований тут; Screen вкладок не додає його вдруге. Меню не ховається за глобальним Keyboard.isVisible(): після переходу з авторизації цей стан може бути застарілим.
- BlurTargetView у ScreenBackground охоплює лише спільний градієнт, не меню: немає рекурсивного захоплення blur. Android SDK 31+ використовує dimezisBlurViewSdk31Plus, старіші Android — прозорий fallback без дорогого RenderScript.

Орієнтири: [Expo SDK 57 BlurView](https://docs.expo.dev/versions/v57.0.0/sdk/blur-view/), [Apple Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars), [Android accessibility](https://developer.android.com/guide/topics/ui/accessibility/views/apps-views).

## Перевірки

TypeScript та native export для iOS/Android. Візуальний прогін у симуляторі виконується з тимчасовою ізольованою моделлю tab state, без обходу SessionGuard у production. Реальний Android, VoiceOver/TalkBack і максимальні системні налаштування варто перевіряти на пристроях перед релізом.

ScrollView меню має flexGrow/flexShrink 0 і мінімальну висоту 56; зовнішній контейнер не стискається й має zIndex 10 для показу над контентом.

## Вкладка блогу

У blog.tsx залишена порожня сторінка зі спільним TabHeader. Кольорові тестові блоки та реалізацію блогу прибрано. Overlay меню й окремий BlurTargetView для вкладки збережені; коли додаватимемо прокручуваний контент, його нижній padding має враховувати висоту меню через useBottomTabBarHeight. Інші вкладки резервують місце для меню звичайним layout.

## Оновлення: фіксований текст

За рішенням власника продукту системне масштабування тексту вимкнене через shared/typography. Меню завжди використовує компактні іконки 32 pt; гілку fontScale з великими іконками/підписами прибрано. Горизонтальна прокрутка на вузьких екранах, мінімальні зони натискання, озвучення назв вкладок, Reduce Motion і Reduce Transparency збережені. Це замінює попередні описи поведінки при великому шрифті вище.

## Мінімальний хедер вкладок

`TabHeader.tsx` — висота 56, відступи з боків 20, назва 16, пошук і дзвіночок без підкладок. Використовується в home, legalization, blog, partners; профіль без нього. Верхню safe area надає Screen, тому paddingTop сторінок дорівнює 0.

Лупа відкриває `components/search/GlobalSearchModal.tsx`. Дзвіночок поки без дії. `hasUnreadNotifications` показує помаранчеву крапку; за замовчуванням false, без API-запитів. `onNotificationsPress` залишений для майбутнього підключення.

## Поточна поведінка

Порядок: головна, легалізація, блог, партнери, профіль. На всіх вкладках меню абсолютне, контент прокручується під ним. Кожна вкладка має власний BlurTargetView; підкладка поза меню прозора. ScrollView додає висоту меню до contentContainerStyle.paddingBottom, а не скорочує видиму область. DetailScreen враховує нижню safe area у прокручуваному контенті, без нерухомої обрізаної смуги.
