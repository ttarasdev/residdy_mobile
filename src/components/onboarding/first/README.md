# Перший онбординг

Маршрут: `src/app/(public)/welcome.tsx` (`/welcome`). Він перевіряє локальне проходження навіть при прямому відкритті. Для повторного перегляду в розробці можна відкрити `/welcome?preview=1`, не очищаючи токен чи дані профілю. Параметр preview діє лише в development.

Порядок: мова → легалізація → документи → консультації → партнери.

- `FirstOnboarding.tsx`: хедер, кнопки, прогрес, обробка завершення/пропуску, Android Back.
- `LanguageStep.tsx`: мовні картки лише для цього сценарію. Використовує глобальний `setLanguage`; польська за замовчуванням, попередній вибір зберігається.
- `FeatureArtwork.tsx`: композиції з існуючих GlassCard, SlateCard, PaperCard та іконок. Це демонстрації функцій, не справжні справи/бронювання користувача.
- `OnboardingIcon.tsx`: експортовані іконки з `assets/system_icons/multi`.
- `first-onboarding.styles.ts`: стилі саме цього сценарію.
- Тексти: `onboarding` у всіх чотирьох `src/i18n/messages/*.json`.

Після Intro `WelcomeProvider` читає локальний `residdy.welcome.v1`. Після входу через TanStack Query отримує `GET /user/me`: якщо `onboardingCompletedAt` є, вступ не показується. Якщо дата відсутня, але локально вступ пройдений, викликається `POST /user/me/onboarding/complete`. Якщо немає ні локального проходження, ні серверної дати — SessionGuard направляє на `/welcome`.

«Почнімо» і «Пропустити» спочатку зберігають проходження локально. Запис на сервер іде після авторизації. Мережеві помилки не стирають локальний результат: запит повторюється через TanStack Query, кожні 30 секунд після помилки у відкритому застосунку та при поверненні з фону. Без локального результату помилка перевірки акаунта показує повторну спробу.

`onboardingCompletedAt` і `profileCompletedAt` незалежні. Перша дата встановлюється сервером один раз явним запитом; друга — при заповненні name, surname, phone, location, lan. Вступ не заповнює профіль і не впливає на підписку. На новому пристрої до входу користувач ще невідомий, тому вступ може показатися. Вихід з акаунта локальний вступ не скидає.

При ширині <350 картки стають вертикальними, без накладання й нахилів. Усі сторінки прокручуються вертикально. Кнопки мають мінімальну, а не фіксовану висоту. Текст має фіксований дизайн-розмір через shared/typography, як і в решті застосунку. Рух 2–3 pt виконується лише на активному екрані; Reduce Motion його вимикає. Reduce Transparency дає щільну підкладку під скляні картки.
