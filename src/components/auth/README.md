# Авторизація

Сторінки в `src/app/(public)/(auth)` складаються з `AuthPage` та форми. Усі поля, кнопки та картки — повторно використовувані компоненти. Figma використана як візуальний орієнтир зі збереженої історії: синій спільний фон, Manrope, напівпрозорі поля, світла основна кнопка, компактний логотип і вкладки Вхід/Реєстрація. Поточний файл Figma недоступний через ліміт MCP.

## Де змінювати

- `components/shared/inputs` — Input, PasswordInput, CodeInput, Checkbox. Не звертаються до API.
- `components/shared/buttons` і `cards` — існуюча бібліотека, використовується формами.
- `AuthPage.tsx` — спільна прокрутка, клавіатура, Back, заголовок і опис. Screen задає safe area.
- `shared/styles/auth.styles.ts` — ширина, відступи, типографіка форм.
- `LoginForm`, `RegisterForm`, `ConfirmEmailForm`, `ForgotPasswordForm`, `ResetPasswordForm` — стан полів, валідація, useMutation та переходи.
- `LegalChecks` — читання документів та окремі чекбокси для актуальних версій; використовується при реєстрації й оновленні згод.
- `ConsentsForm` — підтвердження нових згод після входу, без перевірки підписки.

## TanStack Query

Один `QueryProvider` у кореневому layout. SessionProvider використовує `useQuery`, форми — `useMutation`, актуальні юридичні документи — `useQuery`. Ключі: `session`, `registration-documents`, `legal-requirements` + account ID. Автоматичний повтор мутацій вимкнений. Паролі й коди не передаються як mutation variables; не персистимо query cache. AppState синхронізований із focusManager.

Вхід: POST login → GET account/me → перевірка активного USERS → SecureStore → оновлення session і legal cache. Якщо потрібні згоди — `/consents`, інакше `/home`. Стан підписки не блокує авторизацію.

Реєстрація: поточні registration documents → явні згоди → POST register → confirm-email. Якщо сервер повертає 409 `Email already in use`, викликаємо resend й переходимо до коду; сервер надсилає лист лише pending-акаунтам і контролює cooldown. Інші помилки не запускають resend. Пароль наявного акаунта не змінюється. Для вже активного акаунта на екрані коду є повернення до входу. Після підтвердження пошти сервер повертає ok, а не токен, тому користувач повертається на вхід. Є повторне надсилання коду з локальною паузою 60 секунд; серверні обмеження залишаються остаточними.

Відновлення: forgot-password → reset-password із кодом і новим паролем → вхід із повідомленням про успіх. Пошта передається між формами через тимчасовий AuthFlowProvider. Паролі й коди не записуються в URL/сховище.

## Підключення

У `.env.local` вказати `EXPO_PUBLIC_API_URL` (приклад у кореневому `.env.example`), перезапустити Expo. Локально підключено запущений `residdy_backend` на порту 7777 через LAN-адресу в ігнорованому `.env.local`. Якщо IP комп’ютера зміниться, оновити адресу й перезапустити Expo. Завантаження registration documents перевірене в симуляторі; бекенд зараз повертає тестові документи (`isPlaceholder`). Повний вхід та отримання листа потрібно перевірити своїм тестовим акаунтом. Не вказувати токен у EXPO_PUBLIC змінних.

Валідація: email до 254 символів, новий пароль 8–128 символів, код рівно 6 цифр. Паролі не обрізаються через trim. Login допускає непорожній пароль до 128 символів відповідно до DTO.

Перевірки: `npm run typecheck`, `npm run test:api`, Expo export. Тести використовують підставлені HTTP-відповіді; вони не реєструють реальних користувачів і не відправляють листів.

## Мови та компактний екран

Усі написи — у чотирьох `src/i18n/messages/{pl,uk,en,ru}.json`. Глобальна мова за замовчуванням і fallback — польська; збережений вибір користувача має пріоритет. Мова телефона не впливає. Спільний `components/shared/language/LanguageSwitcher.tsx` підключений в AuthPage і придатний для інших екранів. Деталі — `src/i18n/README.md`.

AuthTabs змінює параметр mode на одному маршруті `/login` через setParams. `/register` залишений як Redirect на `/login?mode=register` для сумісності посилань. Форми перемикає спільний FadeSwap, без переходу Stack. На вході немає підзаголовка, картки реєстрації й окремої кнопки підтвердження пошти. SocialLinks під основною кнопкою показує Instagram/Facebook/TikTok/LinkedIn як візуальні заглушки без посилань (за вказівкою користувача). Іконки перенесені з SVG старого фронтенду в assets/socials.

AuthTabs використовує спільні Card і Button: темний контейнер, padding 5, світла активна вкладка — за конструкцією старого AuthSwitcher. Форму центрує AuthPage; соцмережі передаються окремим footer. TikTok/LinkedIn експортовані з наявної локальної бібліотеки Tilda Icons.

### Анімація форм

`login.tsx` складає LoginForm/RegisterForm в одному AuthPage. FadeSwap розташований у `components/shared/animation`; тривалість 120 мс на зникнення і 120 мс на появу, з підтримкою Reduce Motion. Висоти природні: через центрування положення AuthTabs змінюється. Соцмережі показуються тільки в режимі входу. При перемиканні клавіатура закривається, локальні поля попередньої форми очищаються після її демонтажу.
